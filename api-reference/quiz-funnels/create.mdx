---
title: "Criar quiz de venda"
api: "POST /v1/quiz-funnels"
description: "Cria um quiz completo — abertura, perguntas, opções, pontuação, resultados e checkouts — numa única chamada."
---

**Escopo:** `quiz-funnels:write`
**Idempotency:** suportada

O quiz de venda faz perguntas, soma pontos para cada resultado e mostra o(s) produto(s) do resultado vencedor com botão para o checkout. Esta rota cria tudo numa **transação única**: ou o quiz inteiro é gravado, ou nada é.

## Como a pontuação funciona

1. Você declara os **resultados** em `outcomes`, cada um com uma `key` local (ex.: `"basico"`).
2. Cada **opção** de resposta aponta pontos para essas keys em `points` (ex.: `{"basico": 2}`).
3. Ao terminar, o visitante vê o resultado com **mais pontos**. Em empate, vence o que aparece primeiro em `outcomes`.
4. Se nenhuma resposta pontuar, aparece o resultado com `is_fallback: true` (ou o primeiro, se nenhum for marcado).

<Note>
  A `key` só existe neste payload — serve para ligar opções a resultados antes de existirem IDs. Na resposta, os pontos vêm indexados pelo **ID** do resultado.
</Note>

## Imagens

As três imagens do quiz — abertura (`intro.image_url`), pergunta (`questions[].image_url`) e resultado (`outcomes[].image_url`) — usam o **mesmo formato**: ocupam a largura da coluna do quiz, em proporção **16:9**, com cantos arredondados.

| | Valor |
|---|---|
| **Tamanho recomendado** | **1200 × 675 px** (16:9) |
| Tamanho mínimo | 800 × 450 px |
| Formato | WebP ou JPG (PNG só se precisar de transparência) |
| Peso | até 300 KB |
| Protocolo | URL `https`, acessível publicamente |

<Warning>
  A imagem é **recortada para 16:9 a partir do centro** (`object-fit: cover`). Uma foto vertical ou quadrada perde o topo e a base. Mande já em 16:9 para não ter corte.
</Warning>

- **Por que 1200 px:** a coluna tem até 536 px de largura no desktop e cerca de 350 px no celular; telas de alta densidade (2× e 3×) precisam de pouco mais de 1000 px para ficar nítidas.
- **Margem de segurança:** mantenha texto e rostos longe dos cantos — os cantos são arredondados (14 px) e, em telas estreitas, a imagem fica bem menor.
- **Peso importa:** a imagem de abertura é a primeira coisa que carrega no celular. Acima de 300 KB ela demora mais para aparecer em conexão móvel.
- **Texto na imagem:** evite. O título e a descrição já aparecem logo abaixo, em texto real, legível em qualquer tela.
- **Imagens são opcionais.** Sem imagem, a etapa mostra só o texto — o layout se ajusta.

<Note>
  A miniatura do produto na tela de resultado **não** vem daqui: é a capa (`thumbnail`) do curso ligado ao checkout, exibida em 56 × 56 px (quadrada, recortada pelo centro). Envie a capa do curso em pelo menos **168 × 168 px**.
</Note>

## Pixel da Meta

O quiz dispara `PageView`, `ViewContent` e `Lead` (com consentimento do visitante). Para a Meta ligar esses eventos à **compra** no checkout, o quiz e o checkout precisam usar o **mesmo Pixel**. O Pixel do quiz é escolhido nesta ordem:

1. **Próprio do quiz** — `meta_pixel.pixel_id`.
2. **Herdado dos checkouts** — quando `pixel_id` está vazio e **todos** os checkouts dos resultados usam o mesmo Pixel próprio. O token também vem do checkout.
3. **Configurações** — o Pixel de Configurações → Facebook Conversions API.

| Pixel em uso | Navegador (Pixel) | Servidor (CAPI) |
|---|---|---|
| Próprio ou herdado, com token | ✅ | ✅ mesmo com o CAPI das Configurações desligado |
| Próprio ou herdado, sem token | ✅ | — |
| Configurações | ✅ | Só com o CAPI ligado nas Configurações |

<Warning>
  Checkouts com Pixels diferentes não herdam (é ambíguo): o quiz cai no Pixel das Configurações. Nesse caso, defina `meta_pixel.pixel_id` igual ao do checkout principal — a compra nos outros checkouts não será ligada ao quiz.
</Warning>

<Note>
  A compra (`Purchase`) é sempre enviada pelo checkout, com o Pixel **do checkout**. O quiz não muda isso.
</Note>

## Validação de publicação

Com `status: "published"`, o quiz só é criado se:

- toda pergunta tiver texto e pelo menos 2 opções;
- existir pelo menos um resultado;
- **todo** resultado tiver pelo menos um checkout **ativo**.

Caso contrário a resposta é `422` com `error.type = "quiz_not_publishable"` e a lista `error.problems`. Envie como `draft` para salvar e completar depois.

## Erros

| Status | `error.type` | Causa |
|---|---|---|
| 403 | `authorization_error` | Token sem o escopo `quiz-funnels:write`. |
| 403 | `plan_feature_unavailable` | Plano Autoral Store não inclui quizzes. |
| 422 | `validation_error` | Campo inválido (ex.: `meta_pixel.pixel_id` com letras), `key` repetida, `points` para key inexistente, checkout de outro tenant, mais de um `is_fallback`. |
| 422 | `quiz_not_publishable` | Pediu `published` com quiz incompleto. |
| 422 | `platform_limit_exceeded` | Limite de segurança atingido (200 quizzes por conta). |
