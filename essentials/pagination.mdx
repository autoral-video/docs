---
title: "Paginação"
description: "Estratégias de paginação para listagens — length-aware vs cursor."
---

A API usa **dois estilos de paginação** dependendo do volume esperado do recurso.

## Length-aware (offset)

Recursos de baixo volume usam paginação tradicional com `page` + `total`:

- `GET /courses`
- `GET /courses/{id}/modules`
- `GET /modules/{id}/lessons`
- `GET /media`
- `GET /coupons`
- `GET /quiz-funnels`
- `GET /pages`
- `GET /products`
- `GET /offers`
- `GET /webhooks`

### Request

```http
GET /api/v1/courses?page=2&per_page=25
```

### Response

```json
{
  "data": [...],
  "links": {
    "first": "https://.../courses?page=1",
    "last": "https://.../courses?page=10",
    "prev": "https://.../courses?page=1",
    "next": "https://.../courses?page=3"
  },
  "meta": {
    "current_page": 2,
    "from": 26,
    "last_page": 10,
    "links": [...],
    "path": "https://.../courses",
    "per_page": 25,
    "to": 50,
    "total": 247
  }
}
```

## Cursor (recomendado para alto volume)

Recursos com muitos registros usam **cursor pagination** (mais eficiente em DBs grandes, sem `COUNT(*)`):

- `GET /students`
- `GET /access`
- `GET /payments`
- `GET /subscriptions`
- `GET /leads`
- `GET /checkouts`
- `GET /certificates`
- `GET /questions`

### Request

```http
GET /api/v1/payments?per_page=50
```

### Response

```json
{
  "data": [...],
  "links": {
    "first": null,
    "last": null,
    "prev": null,
    "next": "https://.../payments?per_page=50&cursor=eyJpZCI6MTIzfQ"
  },
  "meta": {
    "path": "https://.../payments",
    "per_page": 50,
    "next_cursor": "eyJpZCI6MTIzfQ",
    "prev_cursor": null
  }
}
```

O próximo cursor fica em `meta.next_cursor` e a URL pronta da próxima página em `links.next`. Na última página, ambos são `null`. Paginação por cursor não informa `total`.

### Iteração

```python
import requests

url = 'https://seu-dominio/api/v1/payments?per_page=100'
headers = {'Authorization': 'Bearer aut_...'}

while url:
    res = requests.get(url, headers=headers).json()
    for payment in res['data']:
        process(payment)
    url = res['links']['next']
```

## Limites

| Parâmetro | Default | Máximo |
|---|---|---|
| `per_page` | 25 | 100 |

<Warning>
  Valores acima de 100 são silenciosamente truncados. Para iterar tudo, use cursor + loop.
</Warning>

## Filtros adicionais

Muitos endpoints aceitam filtros via query string:

```http
GET /api/v1/payments?status=succeeded&gateway=pagarme&user_id=42
GET /api/v1/access?course_id=10&active_only=true
GET /api/v1/leads?status=pending&checkout_id=5
```

Veja a página de cada endpoint para a lista completa de filtros suportados.

## Ordem padrão

Listagens vêm em **ordem decrescente por `id`** (mais recente primeiro). As exceções são `GET /courses/{id}/modules` e `GET /modules/{id}/lessons`, que seguem a ordem definida no curso (`sort_order`). Não há suporte a `?sort=` no v1.
