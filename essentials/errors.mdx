Toda resposta de erro segue o mesmo envelope JSON:

```json
{
  "error": {
    "type": "validation_error",
    "title": "Mensagem legível.",
    "status": 422,
    "errors": { "field": ["..."] },
    "request_id": "9f1c2b7e-0d4a-4c1e-9b8a-2f3e4d5c6b7a"
  }
}
```

`type`, `title`, `status` e `request_id` estão sempre presentes. `code` e `errors` aparecem só quando se aplicam.

## Campos

<ResponseField name="error.type" type="string">
  Categoria do erro: `validation_error`, `authentication_error`, `authorization_error`, `not_found`, `conflict`, `rate_limited`, `plan_limit_exceeded`, `plan_feature_unavailable`, `platform_limit_exceeded` ou um tipo específico do endpoint (ex: `payment_not_refundable`). Use este campo para decidir o tratamento no cliente.
</ResponseField>

<ResponseField name="error.title" type="string">
  Mensagem legível em pt-BR.
</ResponseField>

<ResponseField name="error.status" type="integer">
  Código HTTP. Espelha o status da resposta.
</ResponseField>

<ResponseField name="error.code" type="string">
  Detalhe da causa dentro da categoria (ex: `missing_token`, `token_revoked`, `invalid_idempotency_key`). Presente nos erros de autenticação, IP, tenant e idempotência.
</ResponseField>

<ResponseField name="error.errors" type="object">
  Apenas em `validation_error`. Mapa `campo → ["mensagens"]`.
</ResponseField>

<ResponseField name="error.request_id" type="string">
  Identificador da request — o mesmo valor do header `X-Request-Id` da resposta. Veja [Request ID](/essentials/request-id).
</ResponseField>

## Códigos HTTP

| Status | Significado | Exemplo |
|---|---|---|
| 200 | OK | Listagem retornada |
| 201 | Created | Recurso criado |
| 202 | Accepted | Operação assíncrona aceita |
| 204 | No Content | Delete bem-sucedido |
| 400 | Bad Request | Body malformado |
| 401 | Unauthorized | Token ausente, inválido, revogado, expirado |
| 402 | Payment Required | Limite de uso do plano atingido (ex: máximo de produtos) |
| 403 | Forbidden | Sem escopo, IP não permitido, tenant inativo, plano não inclui o recurso |
| 404 | Not Found | Recurso inexistente ou de outro tenant |
| 409 | Conflict | Request com a mesma `Idempotency-Key` ainda em processamento |
| 422 | Unprocessable Entity | Validação falhou |
| 429 | Too Many Requests | Rate limit excedido |
| 500 | Internal Server Error | Bug do servidor |
| 502 | Bad Gateway | Falha no gateway de pagamento externo |

## Códigos específicos por categoria

### Autenticação (401)

| `code` | Causa |
|---|---|
| `missing_token` | Sem header `Authorization`. |
| `invalid_token` | Token mal-formado ou inexistente. |
| `token_revoked` | Token revogado no painel. |
| `token_expired` | Passou de `expires_at`. |

### Autorização (403)

| `code` | Causa |
|---|---|
| `tenant_inactive` | Tenant suspenso. |
| `ip_not_allowed` | Origem fora do allowlist. |
| (sem code) | Token sem escopo necessário. |

### Validação (422)

| `code` | Causa |
|---|---|
| `invalid_idempotency_key` | Chave de idempotência malformada. |
| (sem code) | Falha de validação de campo. Veja `errors`. |

### Idempotência (409)

| `code` | Causa |
|---|---|
| `idempotency_in_progress` | Outra request com a mesma `Idempotency-Key` ainda está rodando. Aguarde e repita — veja [Idempotência](/essentials/idempotency). |

### Outros

Nestes erros a categoria vem em `error.type`.

| Status | `type` | Causa |
|---|---|---|
| 402 | `plan_limit_exceeded` | Limite de uso do plano atingido (ex: máximo de produtos). |
| 403 | `plan_feature_unavailable` | Plano não inclui o recurso. |
| 422 | `platform_limit_exceeded` | Limite de segurança da plataforma atingido (ex: 200 quizzes por conta). Fale com o suporte. |
| 422 | `quiz_not_publishable` | Quiz incompleto para publicar. Veja `error.problems`. |
| 422 | `upload_rejected` | Arquivo recusado na Biblioteca de Mídia (tipo, tamanho ou armazenamento do plano). |
| 422 | `payment_not_refundable` | Pagamento fora das regras de reembolso. |
| 422 | `partial_refund_unsupported` | `amount` diferente do valor total do pagamento. |
| 422 | `subscription_already_canceled` | Assinatura já cancelada. |
| 429 | `rate_limited` | Rate limit do plano excedido. Inclui `retry_after`. |
| 502 | `gateway_cancel_failed` | Gateway de pagamento recusou ou falhou ao cancelar a assinatura. |

## Exemplo: tratamento robusto

```javascript
async function apiCall(path, options = {}) {
  const res = await fetch(`https://seu-dominio/api/v1${path}`, options);

  if (!res.ok) {
    const body = await res.json();
    const err = body.error;

    // Branch por categoria
    switch (err.type) {
      case 'authentication_error':
        // Token ausente, inválido, revogado ou expirado — veja err.code
        throw new AuthError(err.code, err.request_id);

      case 'rate_limited':
        // Backoff
        throw new RateLimitError(res.headers.get('Retry-After'));

      case 'validation_error':
        // Mostra ao usuário
        throw new ValidationError(err.errors);

      default:
        throw new ApiError(err.title, err.status, err.request_id);
    }
  }

  return res.json();
}
```

## Reportando bugs

Inclua no ticket:

- `request_id` do erro
- Endpoint chamado
- Body enviado (sem segredos)
- Timestamp UTC
- Token (apenas o ID, **nunca** o segredo)
